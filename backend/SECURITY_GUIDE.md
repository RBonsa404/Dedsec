# 🔒 Guide de Sécurité DEDSEC

## 🛡️ Mesures de sécurité implémentées

### 1. **Politique de mot de passe fort**
- **Longueur minimum** : 12 caractères
- **Complexité requise** :
  - Au moins une majuscule
  - Au moins une minuscule
  - Au moins un chiffre
  - Au moins un caractère spécial (!@#$%^&*()_+-=[]{}|;:,.<>?)
- **Validation avancée** :
  - Rejet des mots de passe communs
  - Détection de séquences de caractères (abc, 123)
  - Détection de caractères répétés (aaaa)
- **Force du mot de passe temporaire** : 16 caractères avec tous les types requis

### 2. **Changement de mot de passe forcé**
- **Nouveaux comptes** : Statut `PENDING_PASSWORD_CHANGE`
- **Guard global** : Bloque l'accès tant que le mot de passe n'est pas changé
- **Endpoints exclus** : `/auth/*`, `/change-password`, `/reset-password`
- **Réponse** : Redirection forcée vers `/change-password`

### 3. **Rate Limiting (Limitation de débit)**
- **Global** :
  - 10 requêtes par minute
  - 100 requêtes par heure
- **Endpoints sensibles** :
  - Login : 5 tentatives par minute
  - Changement de mot de passe : 3 par minute
  - Reset mot de passe : 3 par 5 minutes
  - Refresh token : 10 par minute

### 4. **Sécurité HTTP (Helmet)**
- **Content Security Policy** : Restriction des sources de contenu
- **HSTS** : HTTP Strict Transport Security (1 an)
- **X-Frame-Options** : DENY (protection contre clickjacking)
- **X-Content-Type-Options** : nosniff
- **X-XSS-Protection** : Mode block activé
- **Referrer Policy** : strict-origin-when-cross-origin

### 5. **CORS Sécurisé**
- **Production** : Uniquement `https://dedsec-pied.vercel.app`
- **Développement** : `http://localhost:3000`, `http://localhost:3001`
- **Préflight** : Cache de 24 heures
- **Méthodes autorisées** : GET, HEAD, PUT, PATCH, POST, DELETE, OPTIONS

### 6. **Logging de sécurité**
- **Intercepteur global** : Log toutes les requêtes sensibles
- **Événements loggés** :
  - Tentatives de connexion
  - Changements de mot de passe
  - Reset de mot de passe
  - Erreurs de sécurité
- **Informations capturées** :
  - Timestamp
  - Méthode HTTP
  - URL
  - Adresse IP
  - User-Agent

### 7. **JWT Security**
- **Access Token** : 15 minutes
- **Refresh Token** : 7 jours
- **Secret** : Généré automatiquement sur Render
- **Validation** : Vérification stricte de la signature

### 8. **Bcrypt Hashing**
- **Cost factor** : 12
- **Algorithm** : Blowfish
- **Sel** : Généré automatiquement pour chaque mot de passe

## 🚨 Procédures de sécurité

### En cas de tentative d'intrusion :

1. **Vérifier les logs** :
   ```bash
   # Sur Render
   # Dashboard > dedsec-api > Logs
   # Rechercher : [SECURITY_ERROR], [AUTH_ATTEMPT]
   ```

2. **Bloquer l'IP (si nécessaire)** :
   ```bash
   # Configurer ALLOWED_IPS sur Render
   ALLOWED_IPS=192.168.1.1,10.0.0.0/8
   ```

3. **Révoquer les tokens** :
   - Supprimer les refresh tokens dans la base de données
   - Forcer le reconnexion de tous les utilisateurs

### En cas de compromission de compte :

1. **Suspendre le compte** :
   ```sql
   UPDATE "User" SET status = 'SUSPENDED' WHERE email = 'compromised@email.com';
   ```

2. **Réinitialiser le mot de passe** :
   - Utiliser l'endpoint `/auth/forgot-password`
   - Générer un nouveau mot de passe temporaire
   - Forcer le changement de mot de passe

3. **Auditer les activités** :
   - Vérifier les audit logs
   - Identifier les actions suspectes
   - Informer l'utilisateur

## 📊 Monitoring de sécurité

### Indicateurs à surveiller :

- **Tentatives de login échouées** : Pic d'erreurs "Invalid credentials"
- **Rate limiting activé** : Trop de requêtes bloquées
- **IPs suspectes** : Tentatives depuis des géolocalisations inhabituelles
- **Activité anormale** : Actions en dehors des heures de travail normales

### Alertes recommandées :

- **Plus de 5 échecs de login** par IP en 1 minute
- **Tentatives de reset mot de passe** multiples
- **Création de comptes** anormalement élevée
- **Accès depuis nouveaux pays**

## 🚨 Tests de sécurité

### Tests à effectuer régulièrement :

1. **Force brute login** : Tenter plus de 5 logins invalides
2. **SQL injection** : Tenter des injections dans les formulaires
3. **XSS** : Tenter d'injecter des scripts
4. **CSRF** : Tenter des requêtes cross-site
5. **Password strength** : Tester des mots de passe faibles
6. **Rate limiting** : Envoyer plus de 10 requêtes par minute

## 📞 Contact en cas d'urgence

En cas de faille de sécurité critique :
1. Suspendre immédiatement l'application sur Render
2. Révoquer tous les refresh tokens
3. Analyser les logs pour identifier l'ampleur
4. Patcher la vulnérabilité
5. Redémarrer l'application
6. Informer les utilisateurs si nécessaire
